# LLM-style-scientific-paper-recommender-1
## Overview
This project builds a local search and recommendation system over the PubMed Central (PMC) Open
Access corpus (Commercial subset, `oa_comm`). Users can query using short keyword-style
queries or free-form "talk-to-LLM" descriptions. The system retrieves relevant evidence chunks using
dense vector similarity and generates grounded answers using Google Gemini.

## Key features
- Reproducible dataset sampling and download from PMC OA AWS S3 bucket (`oa_comm`).
- Parsing PMC JATS XML into paper metadata plus structured sections.
- Section-aware chunking using BERT WordPieces: 350 WordPieces per chunk with 70 WordPieces overlap.
- Embeddings using SentenceTransformer model: `pritamdeka/S-PubMedBert-MS-MARCO` (768-dim vectors).
- Storage and retrieval in PostgreSQL + `pgvector` with an `HNSW` cosine index.
- Retrieval returns top papers with multiple evidence chunks; Gemini RAG answers are grounded in that evidence.<br><br>

## Setup
Steps to set up the environment.

### Install dependencies
```bash
pip install -r requirements.txt
```
### Configure environment variables
Create a `.env` file with:
- `DB_HOST=`
- `DB_PORT=`
- `DB_NAME=`
- `DB_USER=`
- `DB_PASSWORD=`
- `GEMINI_API_KEY=`

### Database setup (PostgreSQL + `pgvector`)
Enter the values for fields `POSTGRES_USER` and `POSTGRES_PASSWORD` in file `docker-compose.yaml`

Set up the PostgreSQL server:
```bash
docker-compose up -d
```
Run the `ddl.sql` script from database client to create the schema, `pgvector` extension, table and `HNSW` index.

#### Chunks table schema
| Column         | Type           | Notes                                                                           |
|----------------|----------------|---------------------------------------------------------------------------------|
| `id`           | bigserial (PK) | Unique row identifier.                                                          |
| `paper_id`     | text           | PMCID / AccessionID (e.g., PMC11583226).                                        |
| `bucket`       | text           | Section bucket (abstract/introduction/methods/results/discussion/conclusion).   |
| `section_index`| int            | Section index in the parsed document (-1 for abstract).                         |

## End-to-end program flow
This section describes the exact pipeline stages and how they connect:

### 1) Download all of the papers' metadata (`download_paper_metadata.py`)
Run this script in your shell to download all scientific paper metadata from the AWS S3 bucket. This metadata is required for the next step because it tells you where each paper is stored in S3, so you can download the actual papers afterward.
```bash
python download_paper_metadata.py --filelist [path_to_file_list]
```
<br>

### 2) Reproducible sampling + download of the papers (`download_papers.py`)
Reads `oa_comm.filelist.csv`, samples N papers deterministically (seeded), writes `reproducible_output.csv`, and downloads XML files.  
Example: sample and download 10,000 papers:
```bash
python download_papers.py --filelist ./oa_comm.filelist.csv --out_dir ./data --n 10000 --seed 42
```
Re-download the exact same set using the `reproducible_output.csv`:
```bash
python download_papers.py --filelist ./data/reproducible_output.csv --out_dir ./data --existing True
```
<br>

### 3) XML parsing into a structured corpus (`xml_parser.py`)
Each line in `corpus.jsonl` is one JSON object representing a single paper.  
It stores the paper’s identifiers (PMCID/PMID/DOI), title, journal name, publication date/year, author names and affiliations, keywords, and the abstract.  
It also stores the full text split into a list of sections, where each section includes its heading/path info and the section text.  
Finally, it includes “buckets” that group section indices into high-level parts of the paper (e.g., introduction, methods, results, discussion, conclusion).  
Example: 
```bash
python xml_parser.py --input ./data/oa_comm/xml/all --out_dir ./output
```
<br>

### 4) Chunking + embedding + ingestion (`text_chunking.py`)
Reads `output/corpus.jsonl`, chunks text using the BERT tokenizer (350 WordPieces window, 70 WordPieces overlap), generates embeddings using SentenceTransformer (pritamdeka/S-PubMedBert-MS-MARCO), and upserts rows into database table in batches (e.g. `MAX_ROWS = 500`).  
Example:
```bash
python text_chunking.py
```
<br>

### 5) Retrieval + paper ranking + RAG (`paper_retrieval.py`)
Interactive CLI that embeds the user query and retrieves semantically similar chunks via `pgvector` (cosine distance) accelerated by an `HNSW` ANN index. Paper-level ranking is computed using the maximum similarity across a paper’s retrieved chunks, after which the top evidence passages are passed to the Gemini API to produce a grounded, evidence-based response.  
Example:
```bash
python paper_retrieval.py --top-papers 10 --evidence 5
```

## How retrieval works
Retrieval is implemented in SQL by embedding the query, retrieving the top-N nearest chunks by cosine distance (`<=>`), converting distance to a similarity score (`sim = 1 − dist`), scoring each paper by the maximum `sim` across its candidate chunks (i.e., the best match), ranking papers, and returning the top evidence chunks per paper.
- Model: `pritamdeka/S-PubMedBert-MS-MARCO`
- Chunk retrieval: top-N nearest chunks by cosine distance (`<=>`)
- Similarity: `sim = 1 − cosine_distance`
- Paper score: `paper_score = MAX(sim)` per paper (best-matching chunk)
- Output: top-K papers + top-E highest-`sim` evidence chunks each
<br>

## How RAG is used
RAG (in `paper_retrieval.py`) is used to ground Gemini’s answers in retrieved paper evidence. Each request is passed to the model as two blocks: a QUESTION block (the user query) and a CONTEXT block (retrieved excerpts from relevant papers). Gemini is instructed to treat both blocks as untrusted text and to answer only using evidence from CONTEXT and responding “I don’t know based on the provided context.” when the CONTEXT does not support an answer.
